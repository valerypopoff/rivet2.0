# Post-version change inventory and review

## Scope

Baseline: `be437aad477b99b0d71f04d15687469146b1c904` (2026-10-07),
which prepared desktop 2.24.0, Studio Server 1.23.0 and public packages 2.17.0.
Reviewed committed range: baseline through `4a48f0ca2` (23 commits;
316 changed files), plus the pending download-menu, external Subgraph navigation
and sidebar loading-label changes. This is a feature-level inventory: related
follow-up fixes and test/doc changes are grouped with their owning feature.

This review follows owning code paths and failure boundaries, not just commit
messages. Regression evidence is not a production latency measurement or a
guarantee that every deployment configuration is safe. Existing safety contracts
are retained; no storage reset, traffic cutover or production mutation is part of
the review.

## Fixes from this reassessment

1. Evaluation history cursor authority/precision (API helper plus behavior tests).
2. Nested desktop bundle reference binding (editor hook plus browser regression).
3. Graph-port browser fixture made independent of ambient API configuration and
   Evaluation-library bootstrap; narrowed its intercept to actual API paths.
4. Architecture/reference-loading documentation corrected to match current UI and
   explicit manifest behavior.

Avoided broad rewrites where the owner already enforces the intended invariant.
The SQL/immutable-artifact split, revision fencing, controlled writer cutover and
hosted focus boundary are intentional safety mechanisms, not redundant complexity.

deployment qualification gates: these local checks do not replace them.

## Follow-up audit

- Evaluation pagination now invalidates ownership when its overlay unmounts,
  not only when the selected suite changes. A pending older-page response
  previously merged stale headers and replaced the cursor after closing and
  reopening Evaluations. The new browser regression reproduced that failure;
  success and failure responses from abandoned panels are now ignored. A merge
  also checks the current project, suite and requested cursor.
- PostgreSQL history cursor projection now uses explicit UTC ISO text with
  microsecond precision instead of `timestamptz::text`, which depends on session
  `DateStyle` and time zone. Header validation uses the same projection. A
  real PostgreSQL regression with `SQL, DMY` and `Pacific/Auckland` reproduced
  the metadata rejection and verifies exact traversal of three runs within one
  millisecond after the fix. Its temporary table is connection-local and rolls
  back; no durable schema or migration is needed.

Follow-up verification: four headless Evaluation paging cases, 34 API Evaluation
tests, 55 adjacent app state/lifecycle/model tests, real PostgreSQL/S3 async
integration, App/API type checks, full `test:style` and diff whitespace checks
passed. The adjacent app tests were rerun after the policy check finished
rebuilding shared outputs; their initial import failures were not test failures
inside Evaluation behavior.
