# Project

## Description

`Project` is the top-level Rivet document shape. It contains project metadata, all graphs, optional library nodes, optional minimal web apps, optional attached data, project references, and the plugin specs required by project node contents.

Rivet project files keep this YAML shape. In the desktop app, installed plugins are app-level, but project YAML still serializes `plugins` for portability. Rivet derives that list from the plugin nodes used in the project graphs and library nodes, and preserves unresolved plugin specs when a project references plugins that are not installed.

## Definition

```typescript
export type ProjectId = Opaque<string, 'ProjectId'>;
export type DataId = Opaque<string, 'DataId'>;

export type Project = {
  metadata: ProjectMetadata;
  plugins?: PluginLoadSpec[];
  graphs: Record<GraphId, NodeGraph>;
  nodePrefabs?: Record<NodePrefabId, NodePrefab>;
  uiGraphs?: Record<UiGraphId, UiGraph>;
  data?: Record<DataId, string>;
  references?: ProjectReference[];
};

export type NodePrefabId = Opaque<string, 'NodePrefabId'>;

export type NodePrefab = {
  id: NodePrefabId;
  sourceNode: ChartNode;
};

export type UiGraphId = Opaque<string, 'UiGraphId'>;
export type UiComponentId = Opaque<string, 'UiComponentId'>;

export type UiGraph = {
  id: UiGraphId;
  name: string;
  description?: string;
  components: UiGraphComponent[];
};

export type UiGraphComponent =
  | { id: UiComponentId; type: 'text'; text: string }
  | { id: UiComponentId; type: 'markdown'; markdown: string }
  | {
      id: UiComponentId;
      type: 'input' | 'textarea';
      label: string;
      stateKey: string;
      placeholder?: string;
      defaultValue?: string;
    }
  | { id: UiComponentId; type: 'button'; label: string; action: UiGraphAction }
  | { id: UiComponentId; type: 'output'; label?: string; stateKey: string; renderAs?: 'text' | 'json' | 'markdown' };

export type UiGraphAction = {
  type: 'runGraph';
  graphId?: GraphId;
  inputMappings?: { inputKey: string; stateKey: string }[];
  inputs?: Record<string, { type: 'state'; key: string } | { type: 'literal'; value: unknown }>;
  outputs?: { outputKey?: string; stateKey: string }[];
  outputKey?: string;
  outputStateKey?: string;
};

export type ProjectMetadata = {
  id: ProjectId;
  title: string;
  description: string;
  mainGraphId?: GraphId;
  path?: string;
  mcpServer?: MCP.Config;
};

export type ProjectReference = {
  id: ProjectId;
  hintPaths?: string[];
  title?: string;
};
```

## Properties

### metadata

Type: `ProjectMetadata`

Project-level information.

| Field         | Purpose                                                    |
| ------------- | ---------------------------------------------------------- |
| `id`          | Stable project ID.                                         |
| `title`       | Project title shown in the app.                            |
| `description` | Project description.                                       |
| `mainGraphId` | Graph to run by default when no graph is specified.        |
| `path`        | Current project path when known.                           |
| `mcpServer`   | Optional MCP server configuration stored with the project. |

### plugins

Type: `PluginLoadSpec[] | undefined`

Plugin load specs required by the project. App-installed plugins make nodes available globally in the editor. The project only needs plugin specs for plugins whose nodes are actually present in the project graphs or library nodes.

Do not treat this as the app's installed-plugin list. It is the portable project dependency list.

### graphs

Type: `Record<GraphId, NodeGraph>`

All graphs in the project, keyed by graph ID.

### nodePrefabs

Type: `Record<NodePrefabId, NodePrefab> | undefined`

Library nodes, keyed by prefab ID. These source nodes are serialized with the project but are not executable graph nodes and do not have connections. Graphs link to them through `nodePrefabInstance` nodes.

### uiGraphs

Type: `Record<UiGraphId, UiGraph> | undefined`

Minimal web apps, keyed by UI graph ID. UI graphs are declarative component trees saved with the project. They are not executable workflow graphs, cannot be selected as the Main Graph, and do not have nodes or connections. Button actions can run regular graphs in the same project through the app preview or the Node package web-app handler. New button actions use ordered `inputMappings` rows to send web-app data keys to Graph Input IDs, and ordered `outputs` rows to save one or more graph outputs back into web-app data. An output row without `outputKey` stores the whole graph output object; an output row with `outputKey` stores `outputs[outputKey].value`. Legacy `inputs`, `outputKey`, and `outputStateKey` fields remain supported for older project files. A configured `outputKey` must be returned by the target graph, or the action fails with a clear error. Use `validateProjectUiGraphButtonBindings(project)` for non-mutating publication/load diagnostics, and `reconcileProjectUiGraphButtonBindings(previousProject, nextProject)` when committing workflow boundary changes. Reconciliation preserves intentional mapping omissions; it adds new-port defaults only when the action covered the complete previous boundary.

Project deserialization validates every UI component and action shape. `normalizeUiGraph(...)`, `normalizeUiGraphRecord(...)`, and `normalizeProjectUiGraphs(...)` expose the same parser for programmatically assembled projects. Invalid data throws `UiGraphNormalizationError`, whose `issues` include exact graph/component/binding paths. Rivet deterministically repairs missing or duplicate legacy component IDs, but rejects unknown component/action types, missing required fields, wrong field types, and invalid enum values.

### data

Type: `Record<DataId, string> | undefined`

Serialized attached data. Large or shared data can be stored here and referenced from graph content through data refs.

### references

Type: `ProjectReference[] | undefined`

References to other project files. Project references cannot be cyclic.

Each reference can include:

| Field       | Purpose                                                 |
| ----------- | ------------------------------------------------------- |
| `id`        | ID of the referenced project.                           |
| `hintPaths` | Candidate paths used to resolve the referenced project. |
| `title`     | Human-readable title for UI and diagnostics.            |

## Loading a Project

```typescript
import { loadProjectFromFile, runGraph } from '@valerypopoff/rivet2-node';

const project = await loadProjectFromFile('./workflow.rivet-project');
const outputs = await runGraph(project, {
  graph: project.metadata.mainGraphId,
  inputs: {
    prompt: 'Hello',
  },
});
```

If `graph` is omitted in run options, Rivet uses `project.metadata.mainGraphId`.
