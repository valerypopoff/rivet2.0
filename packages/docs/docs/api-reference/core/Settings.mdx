# Settings

## Description

`Settings` contains runtime and editor settings that can be passed into graph execution. It is intentionally optional-heavy: callers only provide the values needed by the nodes and plugins they run.

`RunGraphOptions` extends `Settings`, so these fields are passed at the top level of a graph run options object. `RunGraphOptions` also allows extra top-level fields for advanced runtime cases such as named custom-provider API keys.

## Definition

```typescript
export interface Settings<PluginSettings = Record<string, Record<string, unknown>>> {
  recordingPlaybackLatency?: number;
  defaultNodeColors?: boolean;
  openNodeSettingsOnCreate?: boolean;
  pluginSettings?: PluginSettings;
  pluginEnv?: {
    [key: string]: string | undefined;
  };
  openAiApiKey?: string;
  openAiKey?: string;
  anthropicApiKey?: string;
  googleApiKey?: string;
  customAiApiKey?: string;
  openAiOrganization?: string;
  openAiEndpoint?: string;
  chatNodeTimeout?: number;
  chatNodeHeaders?: Record<string, string>;
  throttleChatNode?: number;
}
```

## Properties

### recordingPlaybackLatency

Type: `number`

Delay between recorded chat messages during playback, in milliseconds.

### defaultNodeColors

Type: `boolean`

When enabled in the editor, newly added supported nodes receive predefined colors.

### openNodeSettingsOnCreate

Type: `boolean`

When enabled in the editor, creating a node opens its settings panel immediately.

### pluginSettings

Type: `Record<string, Record<string, unknown>>`

Settings owned by plugins.

### pluginEnv

Type: `Record<string, string | undefined>`

Environment-like values made available to plugins. In `@valerypopoff/rivet2-node`, if `pluginEnv` is unset, Rivet fills plugin-declared environment values from `process.env`. Custom-provider LLM Chat nodes can still read `pluginEnv[Alternative API key env var]` as an environment-style fallback, but new programmatic integrations should use the named top-level run option configured in `Alternative programmatic key name`.

### openAiApiKey

Type: `string`

Shared OpenAI key used by LLM Chat when its provider is OpenAI and API key source is Configured key. It is also used by legacy Chat, Get Embedding, and OpenAI plugin nodes.

### openAiKey

Type: `string`

Legacy alias for `openAiApiKey`. New code should prefer `openAiApiKey`; Rivet still normalizes both names to the same runtime value for compatibility.

### anthropicApiKey

Type: `string`

Shared Anthropic key used by LLM Chat when its provider is Anthropic and API key source is Configured key. Legacy Anthropic plugin nodes also read this value through the shared plugin-config resolver when no non-empty Anthropic plugin key is stored.

### googleApiKey

Type: `string`

Shared Google Generative AI key used by LLM Chat when its provider is Google and API key source is Configured key. Legacy Google plugin nodes also read this value through the shared plugin-config resolver when no non-empty Google plugin key is stored.

### customAiApiKey

Type: `string`

Shared custom-provider key used by LLM Chat custom providers when API key source is Configured key. Custom-provider nodes fall back to this shared key when they do not have a matching named top-level run option or an env-var-specific key.

### Named custom-provider keys

Type: `string`

Custom-provider LLM Chat nodes can set `Alternative programmatic key name` to a top-level run option name such as `cerebrasApiKey`. Programmatic runs can then pass `{ cerebrasApiKey: '...' }`. `RunGraphOptions` allows these additional top-level keys for named custom-provider credentials.

### openAiOrganization

Type: `string`

Optional OpenAI organization ID for OpenAI-backed calls.

### openAiEndpoint

Type: `string`

Optional explicit endpoint override for legacy OpenAI-compatible Chat behavior. Built-in LLM Chat and Generate using AI use provider-owned endpoints; use the Custom provider base URL for OpenAI-compatible hosts.

### chatNodeTimeout

Type: `number`

Timeout in milliseconds for legacy Chat node calls.

### chatNodeHeaders

Type: `Record<string, string>`

Headers applied to legacy Chat node calls.

### throttleChatNode

Type: `number`

Throttle delay for streaming legacy Chat node data into Rivet.

## Usage

Settings fields are merged directly into [RunGraphOptions](../node/RunGraphOptions):

```typescript
const options: RunGraphOptions = {
  graph: 'Main',
  openAiApiKey: process.env.OPENAI_API_KEY,
  anthropicApiKey: process.env.ANTHROPIC_API_KEY,
  googleApiKey: process.env.GOOGLE_GENERATIVE_AI_API_KEY,
  customAiApiKey: process.env.CUSTOM_PROVIDER_API_KEY,
  cerebrasApiKey: process.env.CEREBRAS_API_KEY,
};
```

When using the Node package, unset shared LLM defaults are filled from `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GOOGLE_GENERATIVE_AI_API_KEY`, canonical `CUSTOM_PROVIDER_API_KEY`, legacy `CUSTOM_AI_API_KEY`, and `OPENAI_ORG_ID` when possible. `OPENAI_ENDPOINT` is not read automatically; pass `openAiEndpoint` explicitly only for legacy Chat compatibility.
