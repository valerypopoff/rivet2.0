## Overview

Evaluates one shared state and optional images against a batch of independent typed questions in one provider request, apart from retries. Every question sees the same state and images. It is not an LLM Chat node and does not stream tokens.

## Settings

**Configuration** selects **Inline** (the existing default) or **From profile**. Profile mode adds a required **Decision AI Profiles** input accepting one [Decision AI Profile](./classifier-profile.mdx) or an ordered Array of profiles. It hides inline model/credential inputs without deleting saved settings. **Export Decision AI settings to profile node** creates and wires a Profile, moves active model/key connections, and preserves evidence connections; the command supports Undo/Redo.

With automatic suspension enabled and supported by the host, each profile has a response deadline (0.5 seconds by default). There is no overall node or fallback-chain deadline. Retry controls remain owned by Decision AI run. Optional **Decision AI Attempts** and **Decision AI Profile Summary** outputs report candidate outcomes and failure reasons. On failure, enabled request/response diagnostics remain inspectable alongside the error; on caught exhaustion, Answers/Usage/Cost are excluded. Successful native bodies belong to the winning candidate, and Cost covers its successful usage only. Attempts also retain safe provider-reported usage from rejected answer batches; Response Inspector includes known failed-request estimates in its aggregate and marks unavailable charges partial/unknown.

**Provider**, **Model** and **API key source**, together with configured-key-name options, are inside the collapsible **Model** section. It is initially expanded, like LLM Chat; click its heading to fold or unfold it. Folding preserves your settings, and the editor remembers your section preference.

- **Provider**: choose **Jev**, **Liquid AI**, **OpenAI**, **OpenRouter**, **Perplexity**, or **SubQ**. All use the same Choice, Score, and Noul question definitions. OpenRouter defaults to Microsoft Decision-1.
- **Model**: defaults to `jev-latest` for Jev, `d1` for Liquid AI, `gpt-6-luna` for OpenAI, `microsoft/microsoft-decision-1` for OpenRouter, `pplx-decider-v1.1-27b` for Perplexity, and `subq-snap-1.1` for SubQ. Leave it blank to use the selected provider's default. An explicit saved model or Model input is preserved when you switch providers; clear an old model to use the new provider's default. Pin a version when downstream thresholds were calibrated against it, and recheck those thresholds when changing models.
- **API key source**: **Automatic** checks the named programmatic key, then environment credentials, then the saved Decision AI key when using default names. Existing graphs retain this mode. **Decision AI settings** uses only Settings → Decision AI's key for the selected provider and fails if missing; it never falls back to a general OpenAI key or environment credentials. **Input port** uses only the API Key input. Jev defaults to `typesafeApiKey` / `TYPESAFE_API_KEY`; Liquid AI to `liquidApiKey` / `LIQUID_API_KEY`; OpenAI to `openAiApiKey` / `OPENAI_API_KEY` (with legacy `openAiKey` checked before environment credentials in Automatic). OpenRouter uses `openRouterApiKey` / `OPENROUTER_API_KEY`; Perplexity uses `perplexityApiKey` / `PERPLEXITY_API_KEY`; SubQ uses `subqApiKey` / `SUBQ_API_KEY`. Custom key names are provider-scoped and available in Automatic. Credentials are resolved on the executor, which may be remote.
- **Timeouts**: configured only in [Decision AI Profile](./classifier-profile.mdx), not on this node. There is no overall node or fallback-chain time limit. Old saved overall-timeout values are ignored. Inline calls and profiles without active automatic suspension wait until completion, provider failure or cancellation.
- **Outputs**: enable **Output usage details** to add estimated cost to Usage. Rivet uses base rates of **$0.042 / MTok input** for Jev, **$0.04 / MTok input** for Liquid AI d1 and SubQ Snap, **$0.10 / MTok input** for OpenAI Decisions, **$0.042 / MTok input** for Microsoft Decision-1 via OpenRouter, and **$0.02 / MTok input** for Perplexity Decisions, with **free output tokens**. Provider premiums are not included. Enable **Output request body** or **Output response body** when you need to inspect the provider exchange. These are off by default.
- **Error behavior**: controls HTTP-status failures, catching other node failures, and retries. See the behavior below. **Repeat times** and **Cooldown, ms** use the same defaults and layout as LLM Chat.

Changing Provider is an authored graph setting, not an input port. Providers added later use this same node and question contract.

When a profile chain fails, its error lists the reasons for each failed request,
including retry numbers and HTTP statuses, even if **Decision AI Attempts** is
disabled. **Decision AI Profile Summary** also shows suspension recovery times
and reliability-service warnings. Enabled request/response bodies remain
inspectable in the failed node and full output view; treat them as sensitive.

## Inputs

- **State**: optional text, image, assembled user message, or an ordered array of these. Native image bytes are converted to base64 automatically. Inline image data URLs and recognizable bare base64 image strings also work. JSON objects and structured arrays remain supported. An unconnected State sends an empty string. There is no separate Images input.
- **Questions 1…N**: one definition or an array/nested array of definitions. A trailing empty port is always available. Arrays are preserved during split runs and recursively flattened in authored order.
- **Model**: shown when **Model from input** is enabled.
- **API Key**: shown when **API key source** is **Input port**. It is never saved in the project.

An empty batch, malformed definition, duplicate Question ID, or invalid criteria fails before a request is made.

## Outputs

- **Answers** (`object`): aggregate answer map keyed by Question ID.
- **Usage** (`object`): provider input and output token counts. When **Output usage details** is enabled and pricing is known, includes `totalCost` in USD using the matched model's rate and context tier; output tokens contribute $0 for the currently priced models.
- **Cost** (`number`): estimated USD cost, included in automatic graph-cost accounting regardless of the Usage-details setting. Excluded when the cost cannot be calculated.
- **Request body** (`object`): available when **Output request body** is enabled. This is the JSON body prepared for the provider after Rivet has resolved State, Model, and Questions; capture does not prove remote delivery. It excludes authorization headers and Rivet-managed API keys, but state and question content are intentionally visible.
- **Response body** (`object`): available when **Output response body** is enabled, including HTTP rejection and invalid answers. JSON objects keep their native shape; non-JSON text or non-object JSON appears as `{ raw: value }`. Captured content is not redacted. Missing, interrupted or over-limit bodies are unavailable.
- **Run failed** (`boolean`) and **Run error** (`string`): available only when **Catch all exceptions** is enabled, independently of **Throw exception on non-2XX status code**. On success, Run failed is `false` and Run error is excluded. On a caught failure, Run failed is `true`, Run error explains the failure, and Answers/Usage/Cost are excluded; enabled diagnostics remain available.

Jev `jev-1.13.0` and `jev-1.14.0` are priced at **$0.042 per million input
tokens**, with free output tokens. Their `jev-latest` and `jev-preview` aliases
also have known pricing when the returned model is one of these verified versions.
See [TypeSafe's model pricing](https://docs.typesafe.ai/models). Unrecognized future
versions remain unpriced rather than being assumed free or assigned an older rate.

When a chain fails, bodies describe its last prepared request, not a mixture of different profiles. Failed-node diagnostics are also retained in recordings. Enable body outputs only when needed: State, questions, images and provider error content may be sensitive. A missing API key before preparation produces no request body. No response body exists when a request never received one, such as a connection failure.

For Jev, Choice answers contain `choice`, `probabilities`, and `confidence`; Score answers contain a numeric `score` (which can be fractional), `legend`, `probabilities`, and `confidence`; Noul answers contain a numeric `noul` probability. These values come from the provider; Rivet does not enforce their numerical ranges.

Rivet checks the response structure, required field types, and question/option/level mapping, then passes the provider's numbers through unchanged. It does not check probability sums, numerical ranges, or derived numerical relationships, and does not round or normalize answers. Malformed responses still fail. This policy applies to every API-compatible Decision AI provider, not only Jev.

Calculated `totalCost` is added only when Usage contains safe, non-negative integer token counts. Otherwise the provider's Usage is still returned unchanged, without calculated cost.

Pricing must also be known for both the requested and returned models. Recognized Jev IDs are `jev-latest`, `jev-preview` and `jev-1.13.0`; Liquid pricing is known for paid `d1`. Unknown models, including `d1:free`, do not inherit a paid default rate and are not assumed free. Their Answers and Usage remain available, but Cost is excluded and Usage.totalCost is omitted.

## Inspecting a run

Hover the node's output and click the **eye** (**Inspect response**) to open the
same summary used by LLM Chat. It is also available in fullscreen output and
from **Run activity**. No optional diagnostic outputs need to be enabled.

The summary shows status, duration, Decision AI requests, retries, profile
fallbacks, reported tokens and estimated cost. Each request identifies its
profile, provider/model, HTTP status, timing and any failure reason. Separate
profile decisions explain suspension, recovery and profiles not reached.
Missing usage or pricing is unknown, not free. Older recordings without this
metadata show **Trace unavailable**.

Run Activity includes Decision AI nodes under **Models and tools**. Search by profile
name, provider or model; expand the row to see attempts, or choose **Inspect
response**. Its totals include available failed-request usage and identify
incomplete retained evidence. Request/response bodies remain in the existing
opt-in output diagnostics, not in these metadata summaries.

The Run Activity inspector updates while that invocation runs. Limited attempt
details are identified explicitly; inferred request counts from older recordings
say **retained evidence only**, not a complete total.

## Resource limits and cost accounting

Rivet limits each evaluation to 32 MiB of expanded request content, 8 MiB of response data, JSON nesting depth 64, 100,000 expanded values, 1,000 questions, 1,024 messages and 4,096 content parts. Native images count at their base64-encoded size. Stricter provider limits still apply. Oversized input is rejected, not truncated or split; reduce the evidence upstream. Repeated references count each time they would appear in JSON.

The always-available **Cost** output is estimated USD cost and contributes to the graph's normal cost total even when **Output usage details** is off. Enabling that setting additionally puts the same estimate in `Usage.totalCost`. Cost is excluded when pricing or safe token counts are unavailable; a genuine zero-token result produces zero. Graph totals sum known costs and may be incomplete when any cost is unavailable. Estimates use successful-response usage and base rates, not an invoice for failed attempts or provider premiums.

Input and response processing retain byte, depth and work limits and check caller cancellation. Enabled profile response timeouts cover provider preparation, retries and response receipt. Individual bounded JSON/base64 operations remain synchronous and cannot be interrupted mid-operation.

For OpenAI `gpt-6-luna` Decisions, requests with more than 272,000 input tokens use $0.20/MTok input for the whole request; smaller requests use $0.10/MTok. Output tokens remain free. Regional and account-specific premiums are not included. See [OpenAI's model pricing details](https://developers.openai.com/api/docs/models/gpt-6-luna).

Cost uses the provider's reported input tokens for the complete request, including billed image tokens and all questions. It does not multiply that total by the question count or add images again. Liquid d1 bills each question's image evidence, but already includes those tokens in Usage. OpenAI Decisions has no separate cache-read, cache-write or output charges; its pricing differs from ordinary Chat/Responses requests using the same model.

## Error behavior

- **Throw exception on non-2XX status code** is enabled by default. Disable it to suppress failed provider HTTP statuses instead of throwing; unavailable normal outputs are excluded. Run failed and Run error appear only when **Catch all exceptions** is enabled. This switch does not bypass response-shape validation: a malformed successful HTTP response still fails.
- **Catch all exceptions** is off by default. Enable it to route node failures, including invalid inputs, missing credentials, transport errors, request timeouts and malformed responses, to the failure outputs. Explicit graph cancellation remains cancellation, not a caught node failure.
- **Retry on non-200** retries non-authentication, non-validation HTTP failures. **Repeat times** is the number of retries after the initial request; **Cooldown, ms** is the fixed wait between them. Despite the setting's name, a valid response with any successful 2XX status is accepted. Malformed 2XX responses are not retried.

Error diagnostics retain underlying causes for debugging and can include provider details or malformed-response fragments. Review them before sharing logs or recordings.

## Execution requirements

All providers require Node execution, Studio Server, the CLI/desktop sidecar, or remote debugging. Browser execution is rejected before any credential lookup. Transient transport failures and HTTP 429/529 share a budget of at most two automatic retries, respecting `Retry-After`, whether or not **Retry on non-200** is enabled. The Error behavior setting has a separate retry budget for other HTTP failures, so a mixed sequence can exceed three requests. An enabled profile response timeout covers all retries of that profile; there is no overall node deadline. Every retry resends the same captured request JSON; the response-body output contains the final successful response. Authentication, validation, insufficient-credit (402) and oversized-request (413) failures are not retried. A profile chain can still try another candidate.

## Using Liquid AI d1

Create a key in [Liquid Console](https://console.liquid.ai), then supply it through Settings → Decision AI → Liquid AI API Key, the `LIQUID_API_KEY` environment variable, the `liquidApiKey` processor setting, or the API Key input port. Select **Liquid AI** in Decision AI run and leave Model blank (or enter `d1`). Existing Decision AI Question nodes and their connections do not need changes. See [Liquid's decision-model documentation](https://docs.liquid.ai/lfm/models/decision-models).

## Using OpenAI Decisions

Select **OpenAI** and leave Model blank or enter `gpt-6-luna`. Supply the key through Settings → Decision AI → OpenAI API Key, `OPENAI_API_KEY`, the `openAiApiKey` processor setting (legacy `openAiKey` also works), or API Key input. OpenAI's native predicate answers become Rivet Noul probabilities; Choice/Score outputs retain the existing maps and zero-based levels. Structured instructions/criteria and JSON State are serialized as text for OpenAI, preserving their contents. Refusals fail the node rather than supplying fake answers. Base estimated cost is $0.10 / MTok input, excluding provider premiums. See [OpenAI Decisions](https://developers.openai.com/api/docs/guides/decisions).

## Using Microsoft Decision-1 on OpenRouter

1. Create an [OpenRouter API key](https://openrouter.ai/settings/keys).
2. On the executor, set Settings → Decision AI → **OpenRouter API Key**, or use `OPENROUTER_API_KEY` / programmatic `openRouterApiKey`. API Key input and custom credential names also work.
3. Select **OpenRouter** in Decision AI run or Decision AI Profile. Clear Model to use `microsoft/microsoft-decision-1`, or enter that exact ID.

No Azure deployment or endpoint configuration is needed. Rivet uses OpenRouter's native Decisions API (currently alpha), not chat completions. Microsoft Decision-1 accepts text and structured JSON, not images. It supports the existing profile fallback, suspension and diagnostic outputs.

Estimated base cost is $0.042 / MTok input with free output for the recognized Microsoft model. Unknown returned model aliases keep cost unknown. OpenRouter's reported charge, when present, remains in **Response Body → usage.cost**. See the [model page](https://openrouter.ai/microsoft/microsoft-decision-1) for availability and rates.

## Using Perplexity Decisions

Select **Perplexity** in Decision AI run or Decision AI Profile. Leave Model blank for
`pplx-decider-v1.1-27b`, or enter `pplx-decider-v1-27b` for the older version.
Supply your key on the executor through Settings → Decision AI → **Perplexity API
Key**, `PERPLEXITY_API_KEY`, programmatic `perplexityApiKey`, or API Key input.

This uses Perplexity's native Decisions API, not Sonar/chat. Text, structured JSON
and shared PNG/JPEG/WebP images work with the existing Question nodes and profile
chains. Rivet preserves ordered image parts inside the native State. GIF and
remote image URLs are unsupported. Each batch allows up to 128 questions; each
image allows at most 2,048 tiles of 32 × 32 pixels (for example 1440 × 1440 or
2048 × 1024). Resize larger images upstream. Requests must fit 32 MiB and fewer
than 262,144 input tokens; the provider checks the token limit. Rivet never splits
the batch or drops evidence. Score levels cannot be null.

Estimated cost is $0.02 / million input tokens with free output for both recognized
models. See the [Perplexity Decisions guide](https://docs.perplexity.ai/docs/decisions/quickstart)
for key creation, availability and current limits.

## Using SubQ Snap

Choose **SubQ** and clear Model to use `subq-snap-1.1`. Supply an executor key
through **Settings → Decision AI → SubQ API Key**, `SUBQ_API_KEY`, programmatic
`subqApiKey`, or the API Key input. It works in inline and Profile modes.
`subq-preview` is a chat model, not a Decision AI model.

Snap accepts shared text, structured JSON and PNG/JPEG/WebP images. Connect an
Image or User-type Assemble Message to State as usual; Rivet converts images to
SubQ's native payload and retains their order with numbered references in text.
Limits: **128 questions**, **100 characters per question ID**, **4 images**,
**4 MiB decoded per image**, **8 MiB decoded total**, and a JSON body below
**13 MiB**. GIF, video and remote image URLs are not supported. Snap checks its
**393,216-token** context limit; oversized inputs fail rather than being truncated
or split into different decisions.

Estimated cost is **$0.04 / million input tokens**, with free output, based on the
current [model catalog](https://docs.subq.ai/using-the-api/models/). The older
launch article lists $0.05; Rivet uses the current model documentation. Unknown
future model IDs remain unpriced. Images are already included in reported Usage.
See the [API reference](https://docs.subq.ai/endpoints/decisions-api/) for preview
access and limits. A 402 response means the account lacks credits and is not
retried. A 403 response means the key lacks access to the requested model; check
key permissions and account model access rather than treating it as an invalid key
(401). These failures can use the next configured Profile without suspending the
unavailable candidate. Inputs/images follow SubQ's [retention policy](https://docs.subq.ai/using-the-api/data-retention/);
zero retention requires provider-side organization settings.

## Multimodal shared State

Connect an Image node directly to **State** for image-only evaluation. For text plus images, use **Assemble Message** with type **User**, just as with LLM Chat: connect text and images to its ordered Part inputs, then connect its Message output to State. Use **Array** to combine multiple user messages or a sequence mixing text with native images. Every question receives this entire shared context; images cannot be attached to individual questions.

For an array of multimodal messages:

1. On each **Assemble Message**, choose **Type → User**, or enable its Type input and pass `user`.
2. Connect the text to **Part 1** and the image to **Part 2** on the same node (more ordered Parts are allowed).
3. Connect each node's **Message** output to **Assemble Prompt**'s **Message 1**, **Message 2**, etc., in the desired order. These inputs also accept existing message arrays.
4. Connect **Assemble Prompt → Prompt** directly to **Decision AI run → State**.

Assemble Prompt combines messages into one ordered `chat-message[]` prompt, not one flattened message. Text/image ordering and message boundaries are preserved. **Array → Output** is also supported as an alternative. If you enable **Filter empty prompts**, whitespace-only text messages are removed, but image-only messages remain. Anthropic cache-breakpoint metadata does not affect Decision AI evidence and is not sent to decision providers.

OpenAI keeps these as separate messages, including each message's ordered text and image parts. Its Decisions endpoint currently accepts **User only**, unlike LLM Chat; selecting System, Developer, Assistant or Function fails before a request instead of silently changing the role. Liquid does not have chat roles: accepted User messages are combined into shared state with blank lines between messages. See the [OpenAI Decisions message schema](https://developers.openai.com/api/reference/resources/decisions).

OpenAI preserves ordered text/image parts in its native `input` messages. Liquid keeps images in its native `images` array and puts numbered `[Image N]` references in the shared text so captions stay associated with the right images. Perplexity keeps inline `image_url` parts in State alongside their captions. Jev uses native image assets with opaque references in the shared State. None turns image base64 into textual evidence. OpenRouter Microsoft Decision-1 and Liquid `d1:free` reject images.

**Jev images are experimental.** `jev-1.14.0`, `jev-1.13.0`, `jev-latest` and
`jev-preview` support still PNG/JPEG images. Connect them to **State**, directly or
with text through Assemble Message. Use images sized **280–1568 pixels per side**,
at most **16 MiB decoded per image**, within Rivet's **32 MiB request limit**.
Rivet enables TypeSafe's experimental image header only when sending images;
text-only calls are unchanged. GIF/WebP are not accepted by Jev: convert them
upstream. Jev also rejects animated/damaged files and requests exceeding its
processed-image or context limits. Input usage already includes image tokens,
so no separate image charge is added. See [TypeSafe's image documentation](https://docs.typesafe.ai/images)
for its experimental status and current limits. This does not add Box questions
or images inside Question definitions.

Use `data:image/png;base64,...` (or JPEG/GIF/WebP) when passing encoded images. Bare base64 is recognized only when decoded image headers identify a supported format; ordinary strings such as `test` remain text. Malformed explicitly marked images fail. Rivet never downloads image URLs or reads paths from State. System/developer/assistant/tool messages, document/audio parts, and explicit URL parts are not supported; use User messages containing text and inline images.

Object/Object Array inputs stay structured JSON, including strings in their fields. Ordinary JSON arrays through Any/Any Array retain their previous meaning. For an explicit text-only content sequence, use String Array or Assemble Message. Arrays containing native images or assembled messages are recognized as multimodal content.

OpenAI allows up to 128 images. Liquid allows up to 8, with the entire JSON request below 4.5 MB (including base64, text and questions), at most 10,000 patches of 32 × 32 pixels, and an aspect ratio no greater than 100:1 per image. Rivet rejects over-limit requests before sending them; resize images upstream if necessary. It never silently drops images or splits the question batch. See [Liquid image requirements](https://docs.liquid.ai/lfm/models/decision-models) and [OpenAI's request schema](https://developers.openai.com/api/reference/resources/decisions).

Optional request/response diagnostics preserve native bodies and may contain complete image data and sensitive authored content. If different questions need different images, use separate Decision AI run nodes with their own State inputs.
