## Overview

A Data Bus is a topology-only node for sharing outputs across a large graph
without drawing long wires everywhere. It is rendered as a pinned, full-width
row below the project tabs rather than as an executable node card. Multiple
Data Buses receive separate rows stacked in graph order.

Each channel has one provider and any number of consumers. Connect a provider
to the next **Connect provider** input, then connect that channel's output to
the inputs that need the same value. Receivers can appear anywhere in the
graph.

The workflow compiler expands every populated channel into direct dependencies
before the graph runs. This means a Data Bus does not wait for all of its
channels, and a later output can be placed on another channel without creating
a false graph cycle.

## Inputs and outputs

| Port       | Type  | Description                                              |
| ---------- | ----- | -------------------------------------------------------- |
| Input [i]  | `any` | The provider for channel _i_. One connection is allowed. |
| Output [i] | `any` | The same channel delivered to any number of receivers.   |

The node adds channels as you connect them. A channel disappears automatically
once it has neither a provider nor any receivers, and its index becomes
available for the next channel. Sparse channels are valid. If a provider is
removed while receivers remain, the channel is shown as **Missing provider** so
it can be repaired.

## Canvas behavior

- Established connections use compact antenna markers instead of long wires.
- Channel ports hang halfway below the lower edge of each rail item, leaving the
  label width available for provider details.
- Hover a channel or an antenna to reveal the actual provider and receiver
  wires in the active color.
- Every Data Bus occupies a full-width row below the project tabs and reserves
  canvas space rather than covering the graph.
- The rail is not draggable. Use its settings button to select and edit the
  Data Bus node.

## Constraints

Data Buses are always-active topology. They cannot be disabled, conditional,
run per item, frozen, or configured with variants. A channel with several
providers is an error; disconnect providers until exactly one remains.

They also cannot be used as a **Run to** target. Choose an ordinary provider or
consumer node instead. Invalid channel wiring fails before the graph begins, so
Rivet can show the exact configuration error rather than silently running an
empty graph.

If a hand-edited project contains incompatible execution settings on a Data
Bus, Rivet shows it as an ordinary node card and offers **Repair Data Bus
execution settings**. Repair clears only those incompatible settings; the bus
title, position, and connections remain unchanged.

Add Data Bus directly from the node list when you need shared canvas topology.
Passthrough nodes no longer have a Data Bus display mode and cannot be switched
into one from their settings. Open the Data Bus settings and select **Delete
Data Bus** to remove the rail and its connections. Data Bus settings do not
offer conversion to Passthrough.

Legacy Passthrough nodes previously configured as canvas data buses remain
ordinary Passthrough nodes when the project opens. Rivet ignores and removes
their retired display flag; it does not convert them into this dedicated node
type.
