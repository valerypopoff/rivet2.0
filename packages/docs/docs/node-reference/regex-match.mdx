## Overview

The Regex Match Node is used to match a string input against a series of regular expressions. Each regular expression corresponds to an output of the node.

The node can be configured to either run the _first_ matching output port, or to run _all_ matching output ports. If no match is found, the `Unmatched` output port will be executed.

This node is useful for routing control flow based on the content of a string. For example, you can use the Regex Match Node to check if a user's message contains certain keywords and route the conversation accordingly.

Choose how values reach the outputs with **Case values**. **One shared value** keeps the original single optional `Value` input: its value reaches every output that matches, or the `Test` value is passed through when `Value` is unconnected. **Values per case** adds a canvas-only **Values** group after `Test`, containing one optional input for every case and one for `Unmatched`. Each input falls back to `Test` independently when it is unconnected. Dotted row guides show which input belongs to each labelled output, so each route can emit its own value and type.

## Inputs

| Case values mode | Title     | Data Type | Description                                              | Notes                                                 |
| ---------------- | --------- | --------- | -------------------------------------------------------- | ----------------------------------------------------- |
| Both             | Test      | `string`  | The string to be tested against the regular expressions. | Required. The input is coerced to a string if needed. |
| One shared value | Value     | `any`     | The value passed to every matching output.               | Optional. If unconnected, `Test` is passed through.   |

| Values per case  | Unmatched | `any`     | The value emitted when no case matches.                  | Shown under **Values**; optional, otherwise `Test`.   |

## Example 1: Route control flow based on AI input

1. Create an [LLM Chat Node](./llm-chat.mdx) and set the `Prompt` to a question, such as:
   > Would you like to hear about information about cats or dogs first? Please only pick one! I will give you information on both, I just want to know what you'd like to hear first.
2. Create a Regex Match Node and connect the `Response` output of the LLM Chat Node to the `Test` input of the Regex Match Node.
3. In the body of the Regex Match Node, set the regular expressions to `cats` and `dogs`.
4. Set **Case values** to **Values per case**. Connect three [Text Nodes](./text.mdx) with the values "You chose cats!", "You chose dogs!", and "Sorry, I didn't understand that. Please try again." directly to the `cats`, `dogs`, and `Unmatched` inputs under **Values**.
5. Connect the Regex Match outputs to the next work for each route.
6. Run the graph. Depending on the AI's response, the corresponding output is executed with its own configured text.

## Error Handling

If the `Test` input is missing, `null`, or `undefined`, the Regex Match Node treats it as an unmatched value. It does not run any case outputs and executes the `Unmatched` output port. If no regular expression matches the test value, the `Unmatched` output port is also executed.

## FAQ

**Q: Can multiple cases match at once?**

A: Yes, multiple cases can match at once. **Trigger all matching cases** is the default. Choose **Trigger first only** to execute only the first matching case.

**Q: Can I use the Regex Match Node to match against numbers?**

A: Yes, you can use the Regex Match Node to match against numbers. However, the `Test` input will be coerced into a string for the matching.

**Q: Can I use the Regex Match Node to match against a list of strings?**

A: Yes, you can use the Regex Match Node to match against a list of strings. However, the `Test` input will be coerced into a string for the matching. The default coercion will put each string on its own line for testing against.
