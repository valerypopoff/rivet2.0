## Overview

**Regex Match (legacy)** is the original regular-expression routing node. It remains available so existing projects keep their saved behavior. New projects should use [Match case](./match-case.mdx), which uses exact plain-text cases by default and can also use regular expressions.

Each configured regular expression corresponds to one output. The node triggers every matching output by default, or just the first matching output when **Matching cases to trigger** is set to **Trigger first only**. If no regular expression matches, it triggers `Unmatched`.

## Inputs and outputs

`Test` is required and is coerced to a string. In **One shared custom value** mode, the optional `Custom value` is emitted from every matching output; an unconnected input falls back to `Test`.

**Custom values per case** adds one optional value input for every regular expression and one for `Unmatched`. Each case independently falls back to `Test` when its custom input is unconnected. The node keeps stable case-output and custom-value port IDs so existing connections remain attached when cases are renamed or reordered.

## Settings

| Setting | Description | Default |
| --- | --- | --- |
| Matching cases to trigger | Trigger every matching regular expression, or only the first one. | Trigger all matching cases |
| Custom case values | Use one shared value for all active outputs, or a separate value for every case and `Unmatched`. | One shared custom value |
| Cases (regular expressions) | The JavaScript regular expressions tested against `Test`. | `YES`, `NO` |

## Error handling

When `Test` is missing, `null`, or `undefined`, no case is matched and the node triggers `Unmatched`. Invalid regular expressions continue to report the existing runtime error.
