## Overview

The Code Node runs JavaScript code and sends the exact returned value to **Output**. Explicit fields in a directly returned object also create named output ports automatically.

It is useful when you want the convenience of the Expression node's `{{input}}` ports, but you also want a normal code body with local variables, multiple statements, `await`, and an explicit `return`.

Use [Code (legacy)](./code.mdx) when you want to work with the lower-level `inputs.foo.value` API and manually configured outputs directly.

### Inputs From Interpolation

Code does not have an `Inputs` setting. Instead, any `{{name}}` token in the code creates an input port named `name`. A JSONPath expression such as `{{customer.address.city}}` still creates only the base `customer` port and evaluates to the selected JavaScript value.

Interpolated inputs evaluate as connected JavaScript values, not as text snippets. For example:

```js
const doubled = {{value}} * 2;
return doubled;
```

If `value` is connected to the number `21`, the node outputs `42`.

Missing interpolation inputs evaluate as JavaScript `undefined`.

The Code editor recognizes `{{name}}` as Rivet interpolation syntax. It still highlights and checks normal JavaScript around the token, but syntax markers caused only by the interpolation token itself are ignored.

### Reading globals without a port

Use `{{@globals.variableId}}` to read the current global value without creating an input port. It is the same per-run value that [Get Global](./get-global.mdx) reads and [Set Global](./set-global.mdx) writes. JSONPath works the same way as for ordinary interpolation, so `{{@globals.profile.user.name}}` and `{{@globals["customer.profile"].names[0]}}` evaluate to their selected JavaScript values:

```js
const name = {{@globals.profile.user.name}};
return name?.toUpperCase();
```

The value is captured when Code starts. This reference does not wait for a writer, create an execution dependency, or make a Set Global node run first; connect a writer explicitly when ordering matters. The Code wrapper gives authored code an isolated copy, so changing a property of an interpolated global does not update the run's global store. Use Set Global to write a global value.

### Accessing Current Graph And Context Inputs

Like Code (legacy), Code can also read the `graphInputs` and `context` variables passed to the JavaScript runner:

```js
const currentUser = context.currentUser?.value;
return currentUser?.name ?? 'Unknown';
```

### Output

Code always has an output named `Output`. Whatever the code returns becomes that output's value:

```js
const fullName = String({{firstName}}) + ' ' + String({{lastName}});
return {
  fullName,
  length: fullName.length,
};
```

The returned value can be a string, number, boolean, object, array, `null`, or JavaScript `undefined`. Rivet displays explicit `null` and `undefined` values as the literal words `null` and `undefined`.

The example above also creates `fullName` and `length` ports. Discovery reads JavaScript syntax without executing your code. Shorthand fields, quoted names, and numeric names are supported. Fields from different direct object-return branches are combined; a field absent from the actual result excludes that output, while an explicitly present `undefined` remains a value.

Only top-level data fields in direct object returns are discovered. Nested objects remain whole values. Spreads, computed keys, methods, getters, and helper-function returns do not add ports. Neither `return result` nor `return condition ? { foo: 1 } : { bar: 2 }` is followed to infer fields; those results remain available through **Output**. Unknown keys added at runtime do not change ports.

Temporarily invalid code retains the last successfully discovered ports and their wires, including after saving and reopening. Once code is valid, its current fields determine the ports. Reordering fields preserves connections. Renaming one unique direct object-property key, such as `foo` to `foo1`, also keeps that field's connection. Rivet only does this when the edit is confined to that one property name; broad rewrites or repeated branch fields are intentionally treated as new fields rather than guessed renames. Removing a field removes its wire, and recreating that exact name restores it through the editor's connection recovery.

## Example: Transform an object

1. Create a Code Node with the following code:

   ```js
   const user = {{user}};

   return {
     id: user.id,
     label: `${user.firstName} ${user.lastName}`,
   };
   ```

2. Connect an object value to the `user` port.
3. Run the graph. The node outputs the returned object.

## Error Handling

If the code throws an error or contains invalid JavaScript, the node errors. In the editor, Rivet shows the failed authored line when it can map the runtime or syntax error back to the Code source.

## FAQ

**Q: How is Code different from Code (legacy)?**

A: Code (legacy) uses manually configured inputs and outputs. You read inputs through `inputs.name.value` and return an object of typed output values. Code creates inputs from `{{name}}` tokens and returns one value directly.

**Q: How is Code different from the Expression Node?**

A: Expression is for a single JavaScript expression. Code is for a code body: you can declare variables, use statements, `await`, and `return`.

**Q: Can I use `require` or `process`?**

A: Yes. `require` and `process` are available only with the Node executor. Browser execution provides `fetch`, `console`, and `Rivet`.

**Q: Is Code a security sandbox?**

A: No. Code nodes execute trusted JavaScript; executor-provided APIs do not make arbitrary or untrusted JavaScript safe to run.

**Q: Can I return `undefined`?**

A: Yes. `return undefined;` produces an explicit `undefined` output value, displayed as `undefined`.
