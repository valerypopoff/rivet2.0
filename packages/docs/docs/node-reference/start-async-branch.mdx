# Start Async Branch Node

The Start Async Branch node lets the foreground path continue without waiting
for one downstream branch. Rivet still owns that branch and waits for it before
the root graph run ends, so execution events, cancellation, costs, and errors
remain part of the same run.

Use this node for side effects that should overlap the foreground work, such as
publishing a progress status while an AI tool is running. It is not a detached
job that can outlive the graph run.

## Inputs and outputs

The node has paired variadic ports. Connecting another input adds another
input/output pair.

| Port             | Data Type | Description                                                                       |
| ---------------- | --------- | --------------------------------------------------------------------------------- |
| Async Input [i]  | `any`     | A value required before the node starts. The node waits for all connected inputs. |
| Async Output [i] | `any`     | The unchanged value from the matching input.                                      |

The foreground scheduler continues as soon as the Start Async Branch node has
received its connected inputs and launched its downstream branch. All of the
node's output ports are released together.

## Wiring rules

An async branch is a closed, side-effect-only subtree:

- It cannot contain a Graph Output node.
- It cannot rejoin the foreground path.
- Nodes inside it cannot require additional values from outside the branch.

If the branch needs several values, connect all of them to the Start Async
Branch node and use its matching outputs. This makes the complete branch
payload visible at the scheduling boundary.

If an async-branch node fails, the foreground path is not retroactively
stopped. The root graph run reports the error when all foreground and async work
has settled. Stopping the root run also stops its async branches.

**Run from here** is available on the Start Async Branch node itself, but not on
nodes inside its async subtree. Replaying a descendant would otherwise require
silently preloading the trigger and could repeat only part of an async side
effect. Run from the owning Start Async Branch when you intend to replay that
subtree.

## Example: show an LLM tool status without delaying the tool

Connect **Delegate Tool Call**'s **Message (fires before the tool call is
invoked)** output to Start Async Branch, then connect the corresponding async
output to a status-reporting node. Rivet launches the status branch and lets the
Delegate invoke its tools without waiting for that branch to finish. The whole
root run still waits for both paths before returning.

Without Start Async Branch, the pre-tool message branch runs normally and the
Delegate waits for it before invoking the tool.
