# Expression Node

The Expression node evaluates one JavaScript expression and returns the result on its `Output` port.

Use `{{name}}` tokens inside the expression to create input ports. Connected values are exposed as JavaScript values, not as wrapped Rivet `DataValue` objects. `{{customer.address.city}}` creates one `customer` port and evaluates the JSONPath suffix against that value.

Use `{{@globals.variableId}}` to read the current per-run global value without creating a port. JSONPath expressions such as `{{@globals.profile.user.name}}` and `{{@globals["customer.profile"].names[0]}}` return the selected JavaScript value. The read happens when Expression starts; it does not wait for Set Global or order parallel branches. Use [Get Global](./get-global.mdx) when you need an explicit connection, typed default, **Wait**, or **On Demand** behavior, and use [Set Global](./set-global.mdx) to change a value.

## Inputs

Inputs are created from `{{name}}` interpolation tokens in the expression body.

## Outputs

| Title  | Data Type | Description                           |
| ------ | --------- | ------------------------------------- |
| Output | `any`     | The value returned by the expression. |

## Settings

| Setting    | Description                            |
| ---------- | -------------------------------------- |
| Expression | The JavaScript expression to evaluate. |

## Notes

Expression is best for compact value transforms. Use the [Code node](./code-new.mdx) when you need statements, local declarations, `await`, or an explicit `return`.

The active executor provides the APIs it supports. Node execution provides `fetch`, `console`, `Rivet`, `require`, and `process`; browser execution provides `fetch`, `console`, and `Rivet`. Expression nodes execute trusted JavaScript; this executor boundary is not a security sandbox.
