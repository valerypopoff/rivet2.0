## Overview

When Rivet is running from a host application running `@valerypopoff/rivet2-core` or `@valerypopoff/rivet2-node`, then you can attach "External Functions" when running graphs or creating a GraphProcessor. The following external function `sum` will sum all of its arguments:

```ts
import { runGraphInFile } from '@valerypopoff/rivet2-node';

await runGraphInFile({
  ...etc,
  externalFunctions: {
    sum: (...args) => {
      return {
        type: 'number',
        value: args.reduce((acc, curr) => acc + curr, 0);
      }
    }
  }
})
```

You can then call these external functions from within a graph using the `External Call` node. The function to call is configured in the editor for the External Call node, and must match the name of the function you passed to `externalFunctions` when running the graph.

External functions are useful for many use-cases, they can do things like:

- Get data from your database
- Call web APIs
- Get user information about who is running the graph
- Anything else you can think of!

### Web app status messages

The External Call function name `setWebAppStatus` is provided automatically by
Rivet for every graph run. Pass the status message as the first argument. When the
graph is running as a web-app action, the message appears below the running Button
or Chat action through the normal progress channel and disappears when the action
finishes, fails, or is aborted. This is available in the desktop preview and in
hosted pages using WebSocket actions; a regular HTTP action cannot display an
intermediate message before its response arrives. Other hosts may receive the
message as a normal graph-progress event or ignore it if they have no UI for it.

The function is reserved by Rivet for web-app actions. Other host external
functions continue to work normally, but a host-provided function with this name
will be replaced for web-app runs. In ordinary runs it reports normal graph
progress and does not require a host-provided external function.

### Web app browser storage

Web-app actions also reserve two External Call functions for compact, persistent,
JSON-serializable data owned by the current browser app:

- `getWebAppStorage(key)` returns the value stored under `key`, or `null` when the
  key is absent.
- `getWebAppStorage()` returns the complete storage object for the current app.
- `setWebAppStorage(key, value)` stores a JSON-serializable value and returns the
  stored value. A later `getWebAppStorage` call in the same graph run sees it.

Keys must be non-empty strings no longer than 512 characters. These functions are
available only while a graph is running as a web-app action. In the desktop builder
they require local editor execution; hosted HTTP and WebSocket actions both support
them.

Rivet stores one JSON object in browser `localStorage` for each combination of
origin, app URL path, and UI graph ID. An app never receives another app's object.
The browser sends the current app's snapshot with an action and applies changed keys
only after a successful action. Storage is local to that browser profile: it is not
server storage, does not synchronize across devices, can be cleared by the user,
and is subject to the browser's storage quota. Do not use it for secrets because
same-origin browser code can read local storage.

External functions are extremely powerful. They can only be used when running Rivet
from a host application, and ordinary custom external functions are not available
when running Rivet in the Rivet application. `setWebAppStatus` is the exception for
ordinary editor runs: Rivet provides it locally for graph progress, and web-app
actions can also use the reserved browser-storage functions described above. Use
[Remote Debugging](../user-guide/remote-debugging.md)
to run other External Call nodes in the Rivet application.

## Example 1: Make a database call from a graph

In this example, we'll create a graph that makes a database call to get metadata about a single user. First, we'll define the external function that will make the database call:

```ts
import { runGraphInFile } from '@valerypopoff/rivet2-node';

const db = {
  async getUser(id: string) {
    return {
      name: 'test user',
    };
  },
};

await runGraphInFile({
  ...etc,
  externalFunctions: {
    getUser: async (userId: string) => {
      const user = await db.getUser(userId);
      return {
        type: 'object',
        value: user,
      };
    },
  },
});
```

Then, in your graph, create an External Call Node, and set the `Function Name` to `getUser`. Create a [Text Node](./text.mdx) and set the text to the user's ID. Connect the Text Node to the External Call Node. The graph should look like this:

![External Call Node Example 1](./assets/external-call-node-example-01.png)

Run your application, and connect the [Remote Debugger](../user-guide/remote-debugging.md) to it. Then, run the graph. You should see the object returned from the database call in the External Call node.

## Error Handling

If the external function errors, then the External Call node will error. If you want to handle errors in the graph, then you can enable the `Use Error Output` setting. This will cause the External Call node to not error, but instead pass the error message to the `Error` output port. If the `Error` port is populated, then the `Result` port will not be ran. You can use an [If Node](./if.mdx) to check if the `Error` port is populated, and handle the error accordingly.

## FAQ

**Q: Can I use external functions when running Rivet in the Rivet application?**

No, external functions are only available when running Rivet from a host application. Connect the [Remote Debugger](../user-guide/remote-debugging.md) to your host application to run external functions in the Rivet application.

**Q: What do I return from an external function?**

You must return a valid [Data Value](../api-reference/core/DataValue.mdx) with a valid [Data Type](../user-guide/data-types.md), for example to return a string:

```ts
{
  type: 'string',
  value: 'hello world',
}
```

**Q: Can I return a Promise from an external function?**

Yes, you can return a Promise from an external function. The External Call node will wait for the Promise to resolve before continuing.

**Q: How are external functions different from raising events?**

External functions are synchronous, and can return data. Raising events are asynchronous, and cannot return data. The Raise Event node will not wait for the event to be handled before continuing, while the External Call node will wait for the external function to return before continuing.
