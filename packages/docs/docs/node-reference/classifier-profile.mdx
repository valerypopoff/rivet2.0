## Overview

Defines reusable provider, model, credential resolution and suspension settings for Decision AI run. Supports Jev, Liquid AI, OpenAI Decisions, Microsoft Decision-1 through OpenRouter, Perplexity Decisions, and SubQ Snap. Connect **Profile** directly to Decision AI run's **Decision AI Profiles** input, or combine multiple profiles with an Array node to create an ordered fallback chain. Set Decision AI run's Configuration to **From profile**. For OpenRouter, clear Model to use `microsoft/microsoft-decision-1`; see [OpenRouter setup](./classifier-evaluate.mdx#using-microsoft-decision-1-on-openrouter). For Perplexity, clear Model to use `pplx-decider-v1.1-27b`; see [Perplexity setup](./classifier-evaluate.mdx#using-perplexity-decisions).

## Settings and ports

SubQ Snap is also supported: choose **SubQ**, clear Model to use
`subq-snap-1.1`, and configure the SubQ API key. Images, limits and cost accounting
follow the same [SubQ setup](./classifier-evaluate.mdx#using-subq-snap) as inline
execution. Capability failures can fall back to another profile without splitting
the question batch or dropping images.

The Model section mirrors Decision AI run's inline provider/model/API-key settings. Credentials are resolved on the executor. Optional **Model** and **API Key** inputs are enabled by their settings. A missing key is represented as an unavailable candidate so Decision AI run can try the next profile; malformed configuration still fails.

The **Model** dropdown includes known models, **Default**, and **Custom model…**
for entering another name. Existing unlisted names open in Custom mode without
being changed. Selecting Default follows the provider's default; selecting a
listed model pins its exact ID. Model-from-input retains its existing behavior.

With automatic suspension enabled on a supported host, **Response timeout** defaults to **0.5 seconds** per candidate. Existing saved values are kept. Fractional seconds are supported with millisecond precision: enter **0.25** for 250 ms or **0.5** for half a second. The minimum is **0.001** seconds. Decision AI run has no separate total chain deadline.

The limit includes preparation, response validation, repeat requests to the same
provider and the waits between them. These retries are automatic for connection
failures and rate limits, or configured in Decision AI run's **Retry on non-200** settings.
They do not get a fresh timeout each time.

The **Decision AI profile suspension** section follows the LLM Profile layout:
an explanation of the host requirement, **Enable automatic suspension**,
then **Response timeout**, **Failures before suspension**, **Failure window** and
**Suspension duration** when enabled, with help beside each setting. When disabled, only
the explanation and enable toggle appear in the section. Timing fields display
seconds. There is no stream-inactivity setting because Decision AI nodes return a
complete response rather than a stream. **Response timeout** appears inside the
section, immediately after the enable toggle. Values remain saved when disabled.
There is no separate overall deadline on Decision AI run. Disabled or unsupported
profile suspension does not apply a response timeout; cancel the run if needed.

**Automatic suspension** is off by default. When enabled, defaults are three availability failures within 300 seconds and a 300-second suspension. Transport failures, timeouts, HTTP 408/429 and 5XX responses count once per exhausted candidate. Authentication, malformed responses, unsupported evidence and graph cancellation do not count. Suspended candidates are skipped; one recovery probe is permitted after expiry.

Studio Server supplies a durable health store and a **Decision AI profile suspension** tab in Project Settings. Standalone integrations must supply the optional profile-health store to activate suspension and its response deadlines; profiles and fallback still work without it.

**Profile** has type `classifier-config`. Its runtime value contains the resolved credential: treat it as sensitive, like LLM Profile output. Node settings do not persist API keys. Only sanitized attempts are safe for reliability diagnostics.

For **Baseten**, select **Elephant-1** or **Mammoth-1** in Model; Default uses
Elephant-1. Both use the same
credential and shared-State image support as inline mode. See
[Baseten setup and limits](./classifier-evaluate.mdx#using-elephant-1-and-mammoth-1-on-baseten).

## Fallback

For example, create two Decision AI Profile nodes, choose **Liquid AI / d1** on the first and **OpenAI / gpt-6-luna** on the second, and configure their credentials. Connect them to Array's first and second inputs, then connect Array's output to Decision AI run's **Decision AI Profiles** input. Set Decision AI run to **From profile**. Connect State and all Decision AI Questions to Decision AI run as usual. Liquid answers the whole batch when available; OpenAI receives the same evidence when Liquid fails or is suspended. Save/reload, linked node prefabs and cross-project Subgraphs preserve this configuration. Enabling Decision AI run's split execution does not split the profile array into independent evaluations.

Array order determines priority. Decision AI run tries the next candidate after a provider, credential, capability or response-validation failure. State and questions are shared and snapshotted before attempts; invalid shared evidence fails before HTTP. Each candidate must support the same evidence. Rivet never drops images to make fallback succeed.

The first fully validated response supplies Answers, Usage, Cost and native request/response diagnostics. Decision AI run's Cost output estimates that successful response. Optional Decision AI Attempts retain usable provider-reported token counts and known cost estimates even when an answer batch fails validation. Response Inspector aggregates those receipts and marks unavailable or unpriced request costs partial/unknown; it does not assume failed requests are free. Decision AI Profile Summary explains the chain without credentials or request bodies. Explicit graph cancellation stops the chain immediately.

Attempts distinguish configuration, capability, authentication, transport, HTTP, timeout, response-parsing and response-validation failures. Unsupported images are a capability failure, never silently dropped. Malformed JSON and malformed answer shapes are distinct diagnostics; neither triggers suspension.
