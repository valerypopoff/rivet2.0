## Overview

The Passthrough Node is a simple node that passes the input value to the output without any modifications. This node can be useful in scenarios where you want to pass a value through a certain path in your graph without altering it, such as grouping together values from different branches of your graph, or controlling how wires flow through your graph.

## Editor Settings

### Render as data bus

Pins the Passthrough to a compact, single-line bus shelf at the top of the
canvas instead of rendering its rectangular node card. The node name, settings,
and horizontally arranged channels stay in one shallow strip. Use this when one
value needs to feed many nodes across a large graph:

- Connect any node output to the bus's next **Connect provider** port.
- Drag from that channel's output port to as many receiver inputs as needed.
- Established bus connections appear as short, angled router-antenna markers
  on providers and receivers instead of long wires.
- Hover an antenna or rail channel to highlight the other endpoints. The
  channel's number shows how many receivers use it.
- While the channel is hovered, Rivet temporarily draws its real provider and
  receiver wires in the active color instead of its radio-connection markers.
  The antennas return when the pointer leaves.
- When its channels outgrow the compact shelf width, the bus expands into a
  dedicated full-width panel row directly below the project tabs. The row
  starts after an open left sidebar, keeps the bus content centered, and
  reduces the canvas height so nodes and controls begin beneath it. Very large
  channel lists still scroll horizontally without displaying permanent
  scrollbars or covering the canvas.
- Several compact bus panels also promote when their combined width exceeds
  the compact limit. In full-width mode, every bus keeps its own panel row and
  the rows stack vertically instead of being combined into one strip. The
  canvas reserves the height of every row. Opening or resizing the left
  sidebar immediately recalculates the remaining shelf space.

While you drag a connection, Rivet temporarily shows the ordinary wire so its
destination remains clear. Use the settings button beside the bus name to open
the hidden Passthrough's settings or turn data-bus rendering off. Shift-click
a bus shelf to include it in multi-selection. Right-click is intentionally
ignored anywhere on the shelf or full-width bus row because it is not a
spatial node card; use the settings button and normal selection hotkeys for
its actions.

This setting changes only the canvas presentation. The project still stores an
ordinary Passthrough node with ordinary connections, and graph execution is
unchanged. Conditional execution and Run per item must be off because hiding
those execution modes in a rail would make the graph misleading. If a project
file contains an incompatible combination, Rivet shows the normal node card
until it is repaired.

## Error Handling

The Passthrough Node does not have any error handling. If an input is missing or null, the corresponding output will also be missing or null.

## FAQ

**Q: What happens if an input is missing or null?**

A: If an input is missing or null, the corresponding output will also be missing or null.

**Q: What happens when a data-bus provider is disconnected but receivers still use that channel?**

A: The channel remains visible as **Missing provider** so it can be repaired.
The receivers are not silently reassigned to another channel.

**Q: What if an imported project contains several providers for one channel?**

A: Rivet marks the channel as **Multiple providers**. Disconnect the channel's
input repeatedly until only the intended provider remains.
