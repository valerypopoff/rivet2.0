## Overview

The Tool node defines a JSON-schema-backed tool/function that an LLM can call in its response.

The output of the Tool node can be passed into the **Tools** port of the [LLM Chat Node](./llm-chat.mdx). To enable this, turn on tool use in the LLM Chat node's **Tools** section.

If you want to pass multiple functions into an LLM Chat node, collect the functions with an [Array Node](./array.mdx), then connect that array to the LLM Chat node's **Tools** port.

A function is defined using JSON Schema, which is a vocabulary that allows you to annotate and validate JSON documents. For more information on JSON Schema, see the [official website](https://json-schema.org/).

You may use interpolation values in the Tool schema the same way you can use them in the Text and Prompt nodes. Wrap your interpolation values in double curly braces, e.g. `{{value}}`.

The Schema editor recognizes those placeholders as Rivet template syntax. JSON validation still applies to the rest of the schema, but syntax markers caused only by interpolation tokens are ignored while you edit.

## Returning a Handler Result Directly

Choose **Result handling: Return directly** when a deterministic handler already
produces the complete user-facing Markdown and another model request would only
repeat it. This takes effect only when LLM Chat has **Auto-continue after
toolcalls run** enabled and the model returns this one declared Rivet tool as the
only call in that round. The handler still runs through the configured or
connected [Delegate Tool Call](./delegate-tool-call.mdx) path. Its exact string
output becomes LLM Chat's final **Response**, with no follow-up provider request.

If a model round contains two or more calls, Rivet uses normal continuation for
the entire round, even if every called Tool is set to Return directly. Missing
settings from older projects behave as **Continue with LLM**. Return directly has
no special effect in legacy Chat, manual Delegate execution, or LLM Chat without
auto-continuation.

For example, a handler graph can return this complete Markdown string through a
string Graph Output named `output`:

````markdown
Dear user, here is your JSON:

```json
{
  "example": true
}
```
````

The full string remains in LLM Chat's messages and, when used by a web-app Chat,
is stored as the ordinary assistant message and sent back in later conversation
history. Fenced `json` blocks in web-app Chat receive Copy JSON and Download JSON
controls automatically.

## Example 1: Define a function that takes a single string parameter

1. Create a Tool node.
2. Set the `Name` to `greet`.
3. Set the `Description` to `A function that greets a user`.
4. Set the `Schema` to the following:

   ```json
   {
     "type": "object",
     "properties": {
       "name": {
         "type": "string",
         "description": "The name of the user"
       }
     },
     "required": ["name"]
   }
   ```

5. Create an [LLM Chat Node](./llm-chat.mdx) and enable tool use in its **Tools** section.
6. Connect the `Function` output of the Tool node to the `Tools` input of the LLM Chat Node.
7. Set the `Prompt` of the LLM Chat Node to the following, using a [Text Node](./text.mdx) or [Prompt Node](./prompt.mdx):

   ```
   Please call the `greet` function with the name "John Doe".
   ```

8. Run the graph. The LLM Chat node should output a tool/function call to `greet` with the parameter `name` set to `"John Doe"`.

## Error Handling

The Tool node will error if the `Schema` is not valid JSON.

## FAQ

**Q: Can I define a function that takes multiple parameters?**

A: Yes, you can define a function that takes multiple parameters by adding more properties to the `Schema`. Each property represents a parameter of the function.

**Q: Can I define a function that takes an array or an object as a parameter?**

A: Yes, you can define a function that takes an array or an object as a parameter by setting the `type` of the property in the `Schema` to `array` or `object`.

**Q: Can I define a function that does not take any parameters?**

A: Yes, you can define a function that does not take any parameters by setting the `Schema` to an empty object (`{}`).

**Q: Can I use the Tool node to define a function that returns a value?**

A: The Tool node defines the call contract and result-handling policy. The handler graph or host external function determines the returned string.

**Q: How can I connect multiple functions to an LLM Chat Node?**

A: You can connect multiple functions to an LLM Chat Node by passing all of the functions into an [Array Node](./array.mdx), and then connecting the Array Node to the LLM Chat Node's `Tools` input.
