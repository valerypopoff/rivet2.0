## Overview

The Get Global Node is used to retrieve a global value that is shared across all graphs and subgraphs. The ID of the global value is configured in this node.

On the canvas, the node title shows an upward arrow icon rising from a baseline so it is easier to distinguish from [Set Global](./set-global.mdx). This icon is only a visual title cue. If an enabled Get Global node uses a fixed `Variable ID` that no enabled fixed-ID Set Global node or configured project global variable sets, the node header shows a triangular warning icon. Dynamic Get Global IDs and Set Global IDs supplied through input ports cannot be checked in advance.

The node can be configured to retrieve the value on demand, which means it will be read when nodes need it, rather than when this node executes. This is useful when the global value might change during the execution of the graph.

The node can also be configured to wait until the variable is available. This is useful when the global value is set by another node that might not have completed its execution when this node runs.

Templates in interpolation-capable nodes can also read a current global value directly with `{{@globals.variableId}}`, a JSONPath expression such as `{{@globals.profile.user.name}}`, or bracket JSONPath such as `{{@globals["customer.profile"].names[0]}}`. These references do not create input ports, wait for a value, or establish ordering with Set Global. Use this node when the graph needs an explicit value connection, typed missing-value default, on-demand read, or wait behavior. See [Interpolation paths](../user-guide/data-types.md#interpolation-paths) for the common template rules and [Code](./code-new.mdx), [Expression](./expression.mdx), [JS Filter](./js-filter.mdx), or [JS Map](./js-map.mdx) for JavaScript-field examples.

In the editor, the search field above `Variable ID` can find fixed IDs from [Set Global](./set-global.mdx) nodes and configured project global variables in Project settings → General, including the complete loaded project-reference tree, then copy the selected ID into `Variable ID`. The search text is not saved with the node. You can still type `Variable ID` manually, and dynamically generated Set Global IDs must still be entered or supplied through the input port.

## Project global variables

Project settings → **General** can define global variables that are saved with the project. They are the same global variables used by Set Global and Get Global; Rivet assigns them automatically before every root run, so a Get Global node can read them immediately even with **Wait** enabled. Choose a data type and provide a matching JSON value; Rivet validates it before it can be saved. Referenced-project values are applied depth-first in declared reference order; the root project takes precedence when more than one project defines the same ID. A Set Global node can overwrite a configured value later in the same run, just as it overwrites any other global value.

Configured project global variables are assigned from the project at the start of each new root run. They are not a replacement for [Context Node](./context.mdx) values, which are supplied by the local environment rather than saved in the project.

## Example 1: Retrieve a global variable

1. Add a [Set Global Node](./set-global.mdx) to the graph. Set the variable name to `myGlobalVariable` and the value to `Hello World` using a [Text Node](./text.mdx).
2. In a separate part of the graph, add a [Delay Node](./delay.mdx) and set the delay to `1000` (1 second).
3. Create a [Text Node](./text.mdx) and set the text to `myGlobalVariable`. Pass the text into the Delay Node.
4. Create a Get Global Node, enable the input for "Variable Name", and pass the output of the Delay Node into the input. Disable the "On Demand" setting.

![Get Global Node Example 1](./assets/get-global-node-example-01.png)

## Example 2: Retrieve a global variable on-demand

1. Add a [Set Global Node](./set-global.mdx) to the graph. Set the variable name to `myGlobalVariable` and the value to `Hello World` using a [Text Node](./text.mdx).
2. Add a Get Global Node and set the variable name to `myGlobalVariable`. Enable the "On Demand" setting.
3. Add an [If Node](./if.mdx). Set the `If` input to the Set Global Node, and set the `Value` input to the Get Global Node. This will wait for both nodes to complete before running, and will pass the Get Global Node's value through to the next node.
4. Add a Text Node and connect the If Node to the Text Node.
5. Run the graph. Notice that the value of the If node is `Function<string>` because the "On-Demand" setting has been enabled, causing the value to not have resolved yet. The value is resolved in the Text Node, and "Hello World" is displayed.

![Get Global Node Example 2](./assets/get-global-node-example-02.png)

## Missing Values

If the global variable is not found and `Wait` is disabled, the Get Global Node returns the default value for the selected data type. For example, if the data type is `string`, the default value is an empty string. If `Wait` is enabled, the node waits until the variable is available before returning the value.

## FAQ

**Q: What is a global variable?**

A: A global variable is a value that is shared across all graphs and subgraphs during a run. Project settings → General can configure one to be assigned automatically when a project run begins, or a [Set Global Node](./set-global.mdx) can set one during a run. A Get Global Node retrieves it.

**Q: Can I set a global variable from a parent application?**

A: No, global variables can only be set from within the graph. Use a [Context Node](./context.mdx) instead to access global variables set by the parent application.
