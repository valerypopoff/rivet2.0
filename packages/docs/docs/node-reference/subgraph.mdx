## Overview

The Subgraph Node allows you to execute another graph within the current graph. This is useful for reusing logic across multiple graphs, or for breaking down complex graphs into smaller, more manageable pieces.

The inputs and outputs of the Subgraph Node are defined by [Graph Input Nodes](./graph-input.mdx) and [Graph Output Nodes](./graph-output.mdx) within the subgraph. The Subgraph Node will automatically update its inputs and outputs to match those of the selected subgraph.

You can choose the graph from the Subgraph node body directly on the canvas, or from the **Graph** setting in the node settings panel. Both controls edit the same Subgraph setting.

If a Subgraph node selects the same graph that contains it, Rivet shows a warning icon in the node header. This direct recursion is allowed, but it is easy to create accidentally and can run indefinitely unless the graph has its own stopping condition.

## Rearranging ports

You can manually reorder a Subgraph node's visible graph input and graph output ports by right-clicking the Subgraph node and choosing **Rearrange inputs/outputs**. While draggable port labels have rounded backgrounds, drag a port label or row up and down; the other labels shift while you drag, so you can drop the port between existing ports. Click outside the node to exit rearrange mode. Drag the circular port handle when you want to create or rewire a connection. The saved order is specific to that Subgraph node instance; it does not rename ports, change connections, or change the keys in the subgraph output object. The optional `Error` output is not part of the subgraph boundary and stays after the graph outputs.

The Subgraph Node also has an optional error output. If enabled, any errors that occur while executing the subgraph will be caught and output from the error output port. If not enabled, errors will cause the entire graph to fail.

## Execution behavior

By default, a Subgraph node executes the full child graph. Child branches that produce unconnected outputs still run, including their side effects and errors.

Enable **Skip unused outputs** on a Subgraph node to run only branches needed by its connected outputs. This setting belongs to that particular Subgraph node, so other calls to the same graph keep their own settings. Connections to disabled or missing consumers do not require an output; a conditional consumer still counts even if it later decides not to run. Running to a downstream node considers only outputs needed by that run.

Skipped branches also skip their side effects and errors, including global or stored-value writes, dataset changes, events, async work, and HTTP/LLM calls. Use this option when the branches are independent. Rivet cannot infer a dependency through shared globals, storage, events, or arbitrary Code. Work shared with a required output still runs; a single LLM or Code invocation that produces several values is not split into smaller computations.

Unused boundary outputs are returned as excluded values. A requested output that produces no value stays missing, allowing downstream nodes to use their normal input defaults; an explicitly excluded requested value stays excluded. If none are needed, Rivet skips the child graph entirely. Runtime metrics reflect the work performed, with zero synthetic cost/duration for a skipped call; a Graph Output explicitly named `cost` or `duration` keeps ownership of its value instead of being replaced by a metric.

Rivet still runs the **full child graph** when you use **Run to here** on the Subgraph itself, when its partial-output forwarding is enabled, or when **Use Error Output** is enabled and the Error output has an active connection. These exceptions preserve inspection, streaming, and whole-graph error handling without changing the saved setting. Referenced Graph Alias, Call Graph, Loop Until, Cron, and tool graph calls are unaffected.

## Example 1: Reuse a graph in multiple places

1. Create a new graph in your project, and add a [Graph Input Node](./graph-input.mdx) and a [Graph Output Node](./graph-output.mdx) to it. Connect the Graph Input Node to a [Text Node](./text.mdx) and connect that node to Graph Output Node.
2. Update the Text node to have the text `{{input}}
Hi, From Subgraph`.
3. In your main graph, add a Subgraph Node. In the editor settings, set the `Graph` to the graph you created in step 1.
4. Connect a [Text Node](./text.mdx) to the input of the Subgraph Node.
5. Set the Text of the Text Node to `Hello Subgraph!`.
6. Run the graph. Note that the text is passed through the subgraph and back to the main graph with the text from the subgraph appended to it.

## Example 2: Handle errors in a subgraph

1. Using the same graphs from Example 1, in the subgraph add a vector store node.
2. Connect all the outputs from the text node to the vector store node.
3. This will cause the Vector Store Node to Error
4. In your main graph, add a Subgraph Node. In the editor settings enable `Use Error Output`.
5. Connect [Text Nodes](./text.mdx) to both outputs of the Subgraph Node.
6. Run the graph. Note that the error is output on the `Error` port of the Subgraph Node, and the `Output` port is not ran.

## Error Handling

If the subgraph errors, then the Subgraph Node will error. If you want to handle errors in the graph, then you can enable the `Use Error Output` setting. This will cause the Subgraph Node to not error, but instead pass the error message to the `Error` output port. If the `Error` port is populated, then the `Result` port will not be ran. You can use an [If Node](./if.mdx) to check if the `Error` port is populated, and handle the error accordingly.

## FAQ

**Q: Can I use the Subgraph Node to execute a graph in a different project?**

A: No, the Subgraph Node can only execute graphs within the same project.

**Q: Can I use the Subgraph Node to execute a graph in a loop?**

A: Yes, you can use a [Loop Controller Node](./loop-controller.mdx) to execute a Subgraph Node in a loop. Each iteration of the loop will execute the subgraph with the current loop value as an input.

**Q: Can I use the Subgraph Node to execute a graph conditionally?**

A: Yes, you can use an [If Node](./if.mdx) to conditionally execute a Subgraph Node. If the condition is false, the Subgraph Node will not be executed.
